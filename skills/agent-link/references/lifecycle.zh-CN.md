# 会话在线租约与自动归档设计

状态：rc.11 实现说明，2026-10-24。保留原设计的阈值和保护边界；基于现有 CLI/MCP、
daemon 与宿主适配器实现，不新增服务。实机验收单独记录。当前缺口一节为 rc.10 的基线。

## 当前缺口

- worker 的 stale（90 秒）/unresponsive（180 秒）只是任务活动提示，不注销会话。
- Endpoint 持久保存，session list 返回全部登记，没有状态/时间过滤和退场命令。
- connected/receiver_at 是一次连接报告，不是持续在线租约；updated_at 也不是最后模型活动。
- 远端目录响应只合并，不撤回缺失项。当前本地缓存共有 12 项（5 个本机、7 个远端），
  这些数字仅为检查时缓存统计，不表示当前在线聊天数。
- 目录只返回前 64 项；DeepSeek profile 超过 64 个可唤醒登记会报错。

因此不能直接拿旧 updated_at 或 task worker 心跳作“清理依据”。应保留稳定身份，
缩小当前可发现、可运行的通信登记集合，而不删除 Codex/DeepSeek/Claude 聊天历史。

## 推荐的四层规则

| 层次 | 建议默认值 | 动作 |
| --- | --- | --- |
| 在线租约 | 宿主每 60 秒确认该原生聊天存在；租约 5 分钟 | 租约失效显示 offline，移出默认在线候选，不判定任务失败 |
| 临时登记 | 未成功接入、未建立任何绑定，24 小时无显式使用 | 满足工作保护条件后软归档，消化测试/中断接入留下的登记 |
| 长期离线 | 连续 7 天无有效在线租约，且 7 天无实际 agent-link 使用 | 满足工作保护条件后软归档；停止这个端点自身的接收器并停止发布 |
| 远端缓存 | 缓存 10 分钟未确认标旧；30 天未收到有效目录不再作为发现候选 | 配对设备的完整目录替换发现视图，保留历史身份引用与绑定 |

以上时间可配置。开着的待命聊天即使数周没发消息，只要宿主在线租约有效，仍能接收唤醒，
不会因“模型没有新回复”退场。显式 pin 的固定协作端点免于自动归档，但 offline 状态照实显示。
手动 paused 与生命周期独立：不能用自动恢复把用户暂停的聊天重新打开。

## 身份、在线状态和使用时间分开

保留现有 endpoint ID、worker、harness/profile、native 映射、别名、绑定和审批范围。
最少增加 last_host_seen_at、lease_expires_at、offline_since、last_used_at、archived_at、
archive_reason 与 pinned。online/offline 可按租约推导；归档是持久的显式状态。

- last_host_seen_at 仅由本机适配器对精确原生聊天成功观察后刷新。daemon 在线、进程 PID
  存在、模型 worker pulse、定时轮询或一条远端消息不能代替原生聊天存在证明。
- last_used_at 只由模型显式 attach、业务发送/处理、任务操作或真实原生接纳更新。
  wake watch 的 get/inbox 轮询、目录查询、接收心跳和到达但未处理的远端消息不刷新它。
- 显式区分存在且 idle/running/等待审批，与宿主不可达/协议不支持/状态未知。现有 Codex
  inspect 会把多种错误合为 waiting_user，实施前须增加独立的只读 presence 结果，不能
  把该旧字符串直接当成功心跳。查询本身不得创建聊天、模型回合或 rehydrate 已归档聊天。
- unknown 不能证明窗口已关闭。它可以导致在线租约失效，但不能解除此前已知的 running、
  等待人类或不确定 admission 保护。没有 presence 能力的 CLI/MCP 显示 unknown/manual，
  不伪装在线；临时未使用登记可按临时规则回收，已绑定端点保守保留或由用户显式退场。
- 启动/从睡眠恢复后保留至少一个 5 分钟重连宽限期，再进行自动归档评估，避免时钟跳变或
  临时宿主重连使整批聊天退场。暂停期间不伪造心跳。

## 归档保护与退场范围

自动归档前在同一轮检查以下条件，有任何一项则跳过并在预览中显示原因：

1. 原生模型仍运行、等待审批/用户输入，或存在未解决的 native submission intent。
2. 会话持有有效任务租约，或尚有发给该会话的未完成任务、未消费结果/文件、待发任务与
   未回传的关联工作、未完成文件传输或待唤醒通知。不能只看到租约过期就假设工作完成。
3. 本机原生存在性不能可靠核验，且没有满足临时未使用登记规则；或端点已 pin。

这些检查要覆盖本机入站和出站引用，不能只看 inbox。元数据探针也不自动冒充完成；遗留
测试任务若成为保护项，应列明供用户决定，不借归档绕过 claim/complete 或历史保留要求。

“退出”只代表退出 agent-link 当前通信登记。仅由 owning adapter/manager 停止明确属于该
端点的 watcher/sidecar，保留配置、队列、去重及 admission journal；不关闭宿主应用或聊天、
不杀用户模型/业务进程、不解绑设备、不自动 leave 既有组、不删消息/附件/数据库。

动态 manager 必须同步移除归档端点的 bridge，避免下一次扫描又把它拉起。未知进程继续
保留；不能依据目录名称/PID 年龄终止用途不明的进程。MCP 进程可能共享，也不能整体关闭。

## 目录、选择与恢复

- 用户默认目录列 online 与 pin 的候选，pin 且离线须清楚标注；离线项和归档项分别可查询。
  内部 manager 使用结构化状态过滤，不能随便改变现有 list 输出使旧客户端把隐藏误作删除。
- 新目录快照只发布当前未归档端点，状态来自拥有设备。本机记录独立的 fetched_at，不能
  用远端 updated_at 延长缓存新鲜度。旧协议端点标 unknown，兼容期间不得猜测已归档。
- 完整快照携带 query ID、设备身份、版本/revision 与完成标记。超过每页 64 项时分页，所有
  页收到且配对认证通过后才替换该设备的发现集合。缺页、乱序、超时、旧响应均不撤回登记。
  仅从发现集合撤回，不删除已有 binding 的精确 peer 引用或消息中的身份信息。
- offline 端点可以按既有规则排队送达，显示等待接收端恢复，不能宣称执行完成。archived
  端点的新业务任务默认返回明确不可用，不改发到同名或最近活跃聊天；fanout 逐项报告结果。
  已在途的消息/结果仍按精确 worker 持久保存，不丢弃、不把远端来信当恢复授权。
- 同一原生聊天下次本地 attach 时复用原 endpoint/worker 并清除归档状态，恢复既有绑定；
  重新核验 native owner，再按原 wake/paused/权限设置接入。新聊天继续获得独立身份。
  远端发现、心跳和来信不自动恢复本机已归档端点，也不授予接入权限。

## 操作入口（rc.11）

- session list：面向用户的当前候选视图；--all / --archived 查看历史及原因，支持分页。
- session detach：当前聊天主动退出通信登记；存在未完成工作时先拒绝并列出保护原因。
- session attach：在该实际聊天里恢复原身份；沿用现有 pause/resume 语义。
- session pin / unpin：用户明确保留固定协作入口，仍按实际租约报告在线与否。
- session gc --dry-run（默认预览，--apply 才写入）：列出候选、触发规则、保留工作和归档后的效果；正式 gc 只软归档。

CLI/MCP 共用 daemon 规则；任何写操作仍受原 write/本机配置权限限制，文件权限独立。
默认每小时在 daemon 内部扫描一次，不另建定时服务，也不唤醒模型来做回收。硬删除历史、
purge 原生聊天和自动改绑其他窗口不在本设计范围。

## 最小实施与验证顺序

1. 补充只读原生 presence、独立在线租约/使用时间及用户目录状态，先消除“永远 connected”。
2. 引入软归档、保护检查和预览；先跑一轮 dry-run，再启用 24 小时/7 天默认规则与 pin。
3. 接好目录分页/完整快照和缓存淘汰；manager 跟随生命周期增减精确端点监听。

复用 rc.10 原会话身份与 inbox ack；迁移旧记录时不把旧时间戳当新鲜心跳，不立即批量归档，
先进入宽限期和可预览状态。

验收须覆盖：idle 但可唤醒聊天长期保活；崩溃/关窗软离线；网络/协议未知不误删；临时登记
过期；running/审批/租约/待处理结果与文件/uncertain intent 保护；睡眠恢复；pin；旧聊天
重开 ID 与权限保持；新聊天隔离；64+ 目录分页无缺失；旧快照不复活归档；另一聊天监听
不受影响。实际删除历史或关闭用户原生聊天不作为“会话清理成功”的判据。

## 已实现的兼容行为

- 新 CLI/MCP 默认 active 视图；`session list --all` 提供 manager 和人工审计的完整视图，
  `--archived` 同时显示已撤回/过期缓存；`--after` 是视图偏移，`--limit` 控制分页。
- 保持 daemon 旧版不带 view 的 list 语义，以兼容已加载的旧管理器。更新管理器显式读取
  all 并按 archived 过滤；profile 不再因超过 64 个会话整体拒绝启动。
- 查询仍发送兼容旧端的 v1 query，新端同时回复 legacy directory 与 directory_page。
  legacy 帧剥离新字段，旧端可继续解析。新端完整收齐配对来源快照后才撤回发现项；
  旧端目录只合并并标 unknown，不猜测缺项就是归档。
- 新 Codex 原生 sidecar 每分钟独立观测精确聊天，不启动模型。DeepSeek presence 仅使用
  已加载集合，不调用可能加载历史的 resolver；无被动接口时报告 unknown 并保护绑定。
- 手工 detach 要求五秒内的新鲜原生观测；Codex CLI 会自动只读核验。活动回合要求退出
  通信时会拒绝，须在实际 idle 时由已授权的本机流程操作。MCP 不暴露伪造 presence 工具。
- `session gc --session FULL_WORKER --dry-run` 可限当前会话；省略 session 的 CLI 扫描
  本机全部登记，MCP preview/apply 仅限其已保留的当前会话。daemon 每小时做安全扫描。
- 老登记第一次启动仅迁移保护元数据，不更新 native 在线时间，至少给予五分钟宽限。
  在线租约、归档、缓存失效都不会删历史、放弃任务或改变 pause/wake/文件权限。
